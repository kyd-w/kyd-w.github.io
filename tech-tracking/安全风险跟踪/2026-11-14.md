# 安全风险快照 · 2026-11-14

> 第二篇。目标：补齐 11-12 建档时维度 2（AI 增强攻击实证）与维度 4（slop-squatting 实证）的空档。素材窗口 2026-01 ~ 11-14，三项 🚨 级变化均已对官方源核实。

## 🚨 变化（三项，均改变攻防假设）

### 1. OpenAI 公布挖洞工业化成本表（2026-11-06 官方文）——攻击边际成本坍塌首次有官方数字

《A thousand fewer paths to root》：自主管线在 Linux 内核跑通**发现→动态验证→可利用性评估→补丁生成→人工复核**全链路（[官方原文已核读](https://openai.com/index/a-thousand-fewer-paths-to-root)）。

| 指标 | 数值（官方口径） |
|---|---|
| 审计目标 | 5,034 个（约 280 万行，≈内核 7%），Scout 阶段仅花 $3,426 |
| 候选发现 | 2,308 个（12 小时内，$316,549） |
| 动态复现 | 1,724 个（74.7%，30 小时，$73,330）——仅 3.1% 属模型分析错误 |
| 可用 exploit | 1,169 个 LPE + 291 个信息泄露 PoC（在开满 SMEP/SMAP/KASLR 的标准发行版内核上） |
| 独立 LPE（去重后） | **948 个**，总成本 **$1,213,430**，单个成功 exploit 均值 **$360** |
| 经济学 | 按历史赏金折算价值 $18.9M–$66.3M = **净盈利 16–55 倍**；kernelCTF 实测 112 小时 $32,936 挖 21 个 LPE（≈全年人工接受量 26 个的 80%），折赏金 ~45 倍 |
| 新技术 | 10 项第三方内核利用专家确认为**全新利用技术**（非模式匹配） |
| 防御侧镜像 | 扫描结束 10 天内：61 个已上游修复、43 个 staging、299 个公开讨论中 |

- 模型代际曲线：7 月 GPT-5.6 Sol 同管线 166 个 LPE 花 $513,690 → 10 月新版 cyber 模型 948 个花 $1.21M（**总量 ×5.7、单位成本还在降**）
- 顺带实证（对维度 5）：cyber 模型先把**测试基建**打穿——QEMU TCG 0-day 被顺手发现利用；OpenAI 已主动测试并修复 Kata / Moby(Docker) / gVisor 中的基建漏洞
- **对本课题的意义**：维度 2 从"趋势公认"升级为"有官方成本曲线"。人力挖洞的稀缺性假设（防御体系的基石之一）正式失效

### 2. curl 赏金计划关停（2026-01-26 官宣，01-31 生效）——防御经济学崩坏的标志事件

- Daniel Stenberg 官宣终结运行 ~7 年的 HackerOne 赏金计划（累计派发 ~$86k、确认 78–87 个漏洞，报道口径略有出入）：[官方博文](https://daniel.haxx.se/blog/2026/01/26/the-end-of-the-curl-bug-bounty)（已核实存在与日期；细节口径以后续报道为参考）
- 死因：**AI slop 洪水**——低质量 AI 生成报告淹没人工分诊，真实漏洞率同步下降。众包防御的 triage 成本被 AI 打爆
- 与 OpenAI 成本表互为镜像：攻击侧能力商品化 + 防御侧人力分诊被淹没，**两端同时被重定价**
- 呼应：CSA 研究笔记（2026-06）呼吁改革协调披露（CVD）政策，2026 年 CVE 预测上调至 ~59,427 个

### 3. LiteLLM v1.107.0 供应链攻击（2026-10-21）——AI 基础设施自身被投毒

- LiteLLM（开源 LLM 网关/代理，~23M 下载）**发布管线被入侵**，恶意 v1.107.0 同时推上 PyPI 与 Docker Hub：[官方事故公告](https://docs.litellm.ai/blog/security-incident-oct-21-2026)
- 载荷：Python `.pth` 启动钩子窃取凭据 + 每小时远程代码加载；模型网关日志本身成为凭据矿（API key 高密度存储位）
- 归因 TeamPCP——此前打过 **Trivy、Checkmarx KICS**（安全工具是被连续打击的同一目标带）；LiteLLM 系**二次**中招
- 微软威胁情报 10-23 发布技术分析：[Inside the LiteLLM 1.107.0 supply chain compromise](https://www.microsoft.com/en-us/security/blog/2026/10/23/inside-the-litellm-1-107-0-supply-chain-compromise-credential-theft-through-python-startup-hooks)
- **对本课题的意义**："供应链=冲击层×新增面交汇"核心论点的新样本——这回被打击的就是 AI 栈自身（网关），且攻击者是职业供应链团伙（非投机脚本小子）

## 格局判断增量（对 11-12 立项框架的检验）

1. **三层判断全部获得实证**：冲击层（OpenAI 官方成本曲线）、防御假设失效（curl 关停）、新增面（LiteLLM 被投毒 + MCP 实案）
2. **新观察——攻防同时被重定价**：OpenAI 同一篇里攻击工业化（948 exploit）与维护者 10 天修 61 个并存；"修复速度军备竞赛"可能是伪命题（Cloudflare：回归测试一天就挤不进 2 小时 SLA，架构隔离 > 提速）
3. **"AI slop"成为独立威胁类别**：curl 之死不是被 AI 攻破，而是被 AI 生成的垃圾**淹没**——攻击成本的坍塌连带着把防御侧的信息处理成本抬上天。这可能是比挖洞工业化更普遍的格局变化
4. 与 [[self-evolving-agents-tracking]] 的交叉更新：自我进化的信任前提（自动更新/自动装载）在本窗口被双向打击——rclone selfupdate 绕过（打击机制）、LiteLLM 管线投毒（打击载体）
