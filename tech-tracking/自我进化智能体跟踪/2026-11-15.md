## 附：3.5 代管线自主化演进注记（本课题基础设施，11-15 讨论归档）

**起因**：W46 验收当日提出——巡检/蒸馏/push 这三个当前由"人工 + Claude 交互会话"承担的环节，能否落到托管 agent。结论：**能，但目标定义需修正**。

### 现状三段式（自主化前的准确画像）

| 层 | 承担者 | 智能程度 |
|---|---|---|
| 采集/打分/发布 | Pi cron + 确定性脚本 | 零智能（固定代码路径） |
| 周报合成 | DeepSeek 单次 map-reduce | 唯一模型环节，但无工具/无迭代/无自检——是"被脚本调用的 LLM"，不是 agent |
| 巡检/蒸馏/push | 人工 + Claude 会话 | 判断密集：验收（截断/push 实锤）、证据分级（标题级 vs 官方核实）、口径修正、增量判断 |

当前系统"已无人值守，但只在无判断区无人值守"——三件事正是判断所在处，故为自主化落地的最后一块。

### 核心判断（用户确认）

1. **目标是闭环自主，不是全托管**：托管 vs 自建是部署形态（正交）；本质是把三环节从 Tier 3 人工断点降级为 Tier 2 agent+验证回路，人退为"例外处理器 + 假设修订者"（套用 [Agent 范式分层架构](../Agent范式跟踪/README.html)）。盯机制（验收回路）不盯单品（托管平台）——课题原则同样适用于自建管线
2. **路径顺序：判断资产显式化 → 载体化**。验收 rubric（当日人工跑的清单：定时器触发/无截断/push 实锤/线上 200）与蒸馏 playbook（增量才写/来源分级/口径修正）目前是会话内 tacit knowledge，先编码成显式资产（= 范式文档"唯一值得重仓的方法论编码层"、三深度第一深度"技能沉淀"），载体后选且随时可换
3. **目标本身会漂移**：补点位 → 跑起来 → 再校准，循环而非一次到达（范式演进速度决定的）

### 托管能力边界速记（官方文档核实，2026-11-15 口径）

cron 定时 deployment ✓（±15% 抖动）｜GitHub 仓挂载 + PAT ✓｜Outcomes 质检器 ✓（rubric 评分+自动返工，GA-in-beta；**验收环节的现成载体，Dreaming 不适用**——它是记忆整理不是质检，且仍 research preview）｜Memory Store 跨 run 游标 ✓｜云沙箱**够不到内网**（192.168.0.x 不可达，巡检面需先"搬出内网"：Pi 管线把 health/log 摘要作为 status JSON 随收件箱同步）｜无 git push 事件触发｜产品 beta（端点带 beta header）｜计费 = token + $0.08/会话小时（Opus 1h ≈ $0.58，周频任务可忽略）

### 安全边界（安全课题交叉，内部版）

自主 push 的 agent = 把 rclone selfupdate / LiteLLM 管线类风险接到自己仓上——落地形态硬约束：**draft 分支 only + 验收门 + 审计轨迹，绝不直推 main**。这是本课题新 watch「agent 治理」的内部应用。
