# AgentRQ（agentrq/agentrq）项目调研

> 调研日期：2026-10-12 ｜ 来源：GitHub repo/API（当日快照：1,146 ⭐ / 85 fork，2026-03-24 创建）+ 官网 agentrq.com + HN 记录 ｜ 触发：热点求证（"Go 语言的 agent 框架"）
> 状态：**认知归档**——项目真实且活跃，但"特别热"不成立（数据见 §4）；两条触发线见 §7

## 1. 一句话定位

Human-in-the-loop（HITL）的 **agent 任务管理控制平面**：让 Claude Code / ACP 兼容 agent 能"给人派任务、等人回复、恢复执行"——agent 自主干活，卡在需要人类决策的点时通过 MCP 通知通道实时呼叫操作者，人从手机/Web/桌面任意端回复，agent 无损续跑。Go 后端（4.34MB）+ Vue 前端（1.12MB）+ JS（3.81MB），AGPL-3.0，可自托管，公司 Contextual, Inc.，主创 mustafaturan（1,085 commits），SaaS 版 agentrq.com beta 免费。

## 2. 核心定性（对原始印象的两处修正）

**它是"控制平面"，不是"agent 框架"**——不是用来构建 agent 的（LangChain/Eino 那类），而是管理已经在跑的 agent 群的人机协作断点。解决的问题：agent 长任务中"何时该问人、人在哪、怎么问、怎么续"。

**Go 的说法成立但要看比例**：后端确为 Go（API/MCP/gateway/tunnel），前端是 Vue；说"Go 项目"对，说"Go 框架"不准——更像一套用 Go 写的 agent 运维服务。

机制拆解（四件套）：

```
1. MCP 通知通道     Claude Code 原生 <channel> 推送（官网称 <1s 送达）
2. Workspace MCP   每个 agent 一个独立 MCP 端点（独立 persona/任务域）
3. Supervisor MCP  mcp.agentrq.com/mcp 一个入口统管 agent 群
4. ACP 网关        acp-gateway 一条命令接入 55 个 ACP 兼容 agent
                   （Gemini CLI/Codex CLI/Cursor/Copilot/OpenCode/Goose/Devin…）
                   DeepSeek Harness 原生直连，不走网关
```

功能面（官网 15+ 实录 GIF）：cron 任务调度、events/workflows（事件自动派生下一任务+可视化管线）、workspace memory（跨任务共享记忆）、distributed skills（带版本的 agent playbook）、**machines（在自己电脑上跑 agent + 远程看终端）**、tool call history（全轨迹可检索）、message send delay（发送倒计时防误触）、Slack 团队协作、本地 Whisper 语音派单、任务时间线、clear context（每任务干净上下文省钱）。

## 3. 架构观察

- **协议中立是最大差异化**：MCP（上下行）+ ACP（agent 接入）双开放协议，不锁 agent 厂商——押注"agent 会很多家"的未来，与各家平台自带管控功能错位竞争
- **单仓 monorepo**：Go 服务 + Vue UI + Docker 镜像（tunnel-client 等），自托管路线认真（AGPL 而非纯 SaaS 条款）
- 发布节奏极快：v0.9.18 发布于 2026-10-11（调研前一日），仍未 1.0；commit 里有 google-labs-jules[bot]（20 commits）——AI 参与开发自身
- 有趣的自举叙事：官网 landing page 由 Claude 通过 AgentRQ 远程派单建成（营销，但演示了产品闭环）

## 5. 净值判断

| 维度 | 判断 |
|---|---|
| 赛道 | agent ops / HITL control plane——agent 数量膨胀后"人机打断点管理"是真痛点，但赛道拥挤（各家 agent 平台都在原生做审批/通知） |
| 差异化 | 协议中立（跨 55 个 agent）+ 自托管 + Go 部署轻；风险是平台原生功能挤压生存空间 |
| License 陷阱 | **AGPL-3.0**（官网页脚误标 Apache-2.0，以仓库 LICENSE 为准）——内部自用 OK；若嵌入产品向客户提供服务（套餐 B 形态）触发网络条款须开源，**只能参照不能闭源白嫖** |

## 6. 与投石的关联（克制三条）

1. **自用评估**：当并行跑多个 Claude Code 工作区、夜间 agent 任务"等人决策"成为实际摩擦时，自托管一套试 HITL 闭环（MCP 接入对现有 Claude Code 工作流零侵入）
2. **亮哥 AgentInfra 邀约线的开源对照组**：agent ops 赛道小而认真的样本——其"MCP 通知通道 + 每 agent 独立 workspace"设计值得抄；AGPL 决定了它的定位是参照物而非可整合组件
3. **范式信号**（与 REA 调研呼应）：2026 年 agent 中间件的两个方向——REA 给 agent 接"物"（专业工具），AgentRQ 给 agent 接"人"（决策断点）；中间件层的共识是 **MCP 为默认协议**

## 7. 后续动作

- 无近期行动项；观察其 1.0 节点与商业化定价（beta 免费不可持续）
- **触发线一**：自己并行 ≥3 个 agent 工作区、人机打断成痛点 → 自托管 20 分钟实测（Go 单二进制 + Docker，上手成本低）
- **触发线二**：亮哥 AgentInfra 线推进到方案阶段 → 将其列为 agent ops 开源对照组做功能对标
