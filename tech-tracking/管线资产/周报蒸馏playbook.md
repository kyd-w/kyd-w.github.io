# 周报蒸馏 Playbook（判断资产 2/2）

> 3.5 代管线自主化点位清单第 2 项产物（见 [自我进化智能体跟踪/2026-11-15.md](../自我进化智能体跟踪/2026-11-15.html) 演进注记）。
> 把 W45/W46 两轮"周报 → 课题快照"人工蒸馏的操作标准显式化。**当前由人工 + Claude 会话执行（Tier 3），目标为云沙箱蒸馏试点接管草稿、人审合入（点位 4）**。届时本文件即试点 agent 的作业指令。
>
> 版本：2026-11-17 首版（依据：W45→11-08、W46→11-15 两次蒸馏实操归纳）

## 定位

- **输入**：通过验收 rubric 的周报（[周报验收rubric.md](周报验收rubric.html) 前置条件）
- **输出**：各活跃课题的日期快照（`{课题目录}/YYYY-MM-DD.md`）+ 课题 README 活文档增量 + 控制面 commit
- **蒸馏 ≠ 摘要**：摘要是压缩信息，蒸馏是**在课题框架内做增量判断**——同样的周报，对四个课题产出的是四份不同的判断

## 三原则（核心，来自 11-15 注记）

1. **增量才写**：对比上次快照，新事实/有升级的旧事实才落笔。无增量 → 不写快照（不是每周必有产出）。重复出现但无升级 → 至多并入旧条目标"持续出现"
2. **来源分级**：置信度只可降不可升——周报给的"中"就是"中"；升级到"官方核实"只能发生在人工/agent 打开原文核实并标注来源之后
3. **口径修正**：合成模型的表述 ≠ 课题口径。蒸馏时翻译成课题自己的分析语言，纠正常见错位（见下表）

### 常见口径修正对照

| 周报/通稿常见说法 | 课题口径 |
|---|---|
| "System One 类模型" | 品类名是 **decision model**，System One 是 Jev 的型号 |
| "自我进化 AI / 数字生命"（营销词） | 归入三深度框架：技能沉淀 / 模式工程化 / harness 自我改写，标注处于哪层 |
| 单一 CVE / 单品退热 | 安全课题："单一 CVE 不算新闻，格局变化才算"；自我进化课题："单品退热不算新闻，范式迁移才算" |
| 厂商通稿数字（star、性能、融资） | 一律"待验证"，标注口径来源与日期 |

## 流程（八步）

### 1. 备输入（四件）

周报原文 URL ｜ 课题 README（活文档，现状+watch）｜ 该课题**快照链**（最新一份为增量基线；回溯更早快照以核对挂起动作的顺延计数与历史判断线索——W46 dry-run GAP-1/2 教训）｜ `_topics.yaml` 该课题 watch 项

### 2. 逐课题路由

按周报条目的 `topic` 字段分拣；`general` 条目过一遍各课题 watch 项，命中才领走（宁缺勿滥——不相关的硬凑会稀释快照）。

### 3. 对照 watch 项（命中与未命中都记录）

逐条核对课题注册的 watch 信号有无进展。**未命中也写**（"仍无直接证据，watch 未命中，如实记录"——11-08 快照第 3 条例）；watch 全空转多周本身是信号（方向退热或观察项设错）。

### 4. 证据分级落表

| 级别 | 判据 | 快照中的标注 |
|---|---|---|
| 标题级待证实 | 仅管线合成，单一来源 | 头部统一声明 ⚠️ + 表内置信度照抄周报 |
| 中置信 | 合成自评中/高，或有第二个独立来源呼应 | 照抄，注明"双源" |
| 官方核实 | 蒸馏时核实了官方公告/仓库实锤 | 标来源链接 |

### 5. 增量判定

对每条候选事实问三个问题：上次快照有吗（新行）？上次有、本周有升级吗（更新行+升级说明）？上次有、本周原样重复吗（并"持续出现"，不入新行）？

### 6. 写快照（模板，归纳自 11-08 / 11-15 实例）

```markdown
# {课题名} · 快照 YYYY-MM-DD

> 数据来源：TechRadar W{ww} 周报蒸馏（N 条周素材，DeepSeek 分批合成）｜[周报原文](URL)
> ⚠️ 证据等级：标题级信号——除标注外均待证实，置信度为合成模型自评
> 结论先行：有无 🚨、本周最重要的 1–2 个判断

## 本周事实（W{ww}）
| # | 事实 | 置信度 | {课题框架归类列} |    ← 机制层/冲击层等课题自有维度

## 判断
编号列表，每条挂课题框架锚点（见下）

## 与其他课题交叉      ← 有才写，相对链接互指（../Jev跟踪/2026-11-15.md 式）

## 下次关注
- 具体可执行的核对动作（含挂起项纪律，见第 8 步）

## 来源
周报管线条目名 + 交叉核实的文件
```

**判断写法**：每条判断必须挂到课题的框架资产上（自我进化 = 两层框架/换代史/三深度；Jev = 品类验证与护城河指标；安全 = 攻防格局两层；Agent范式 = 分层架构）。挂不上的判断多半是复述，删。

### 7. 更新 README 活文档

快照日志表加一行（日期｜文件链接｜一句话要点，要点写**判断**不写流水）；"现状"列/换代史表有变化才动（自我进化课题换代史表：**无新载体单品就不加行**）。

### 8. 挂起动作纪律 + 收尾

- 下次关注里的动作**顺延 ≥2 次必须标"优先"**；≥3 次要么本期内做掉、要么显式写"降级为不跟踪"并给理由（反面教材：GenericAgent 仓库实测，11-08 挂起→三次顺延）
- commit message 惯例：`docs: W{ww} 周报蒸馏入课题快照（MM-DD）——{两三个要点}`；多课题同日可合一个 commit
- 收尾三连：`git add 课题目录 docs/ _topics.yaml(若改)` → `git commit` → `git push pi main`

## 移交注记（给点位 4 云沙箱试点 agent）

- 试点形态：cron → 挂公开仓 → 读周报 + 课题 README + 本 playbook → **快照草稿推 `weekly-draft` 分支**（draft only 硬约束）→ 人工审后合入控制面
- agent 可做：第 1–6 步全部（纯读公开仓 + 写 markdown）
- 人保留：第 7–8 步的合入决定、🚨 判定复核、置信度升级（"官方核实"级必须人核或 agent 给出可点开的来源由人抽查）
- agent 的自检口径：产出快照须通过 rubric 思想的镜像检查——来源声明齐、置信度无越级、增量对比给了基线日期
