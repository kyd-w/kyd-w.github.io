# REA（morluto/rea）逆向框架调研

> 调研日期：2026-10-12 ｜ 来源：GitHub repo/API（当日快照：131,705 ⭐ / 29,466 fork，2026-04-14 创建）+ 官网 rea.tools + 36kr/虎嗅/oschina/知乎报道 ｜ 触发：媒体爆点跟踪
> 状态：**认知归档**——真爆点（数据支撑，非媒体泡沫）；两条触发线见 §7

## 1. 一句话定位

"Reverse Engineer Anything"：把逆向工程变成 Coding Agent 的一项本地能力——一个 Node.js 写的 **MCP server + 配套 skill**，让 Claude Code/Codex/Cursor/Gemini CLI 等 agent 能检查、反编译、解释并**基于证据重建**无源码程序的功能。MIT，TypeScript 主体（15.7MB TS+JS），3 人核心团队（morluto 1295 / N0zoM1z0 462 / kaoru0822-kitauji 387 commits），npm 包 `rea-agents`。

## 2. 核心定性（本次调研最重要的判断）

**它不是新的 IDA/Ghidra，而是"Agent-native 逆向中间件"**——不重造分析引擎，把本机已有的 Hopper/Ghidra/IDA 包装成 agent 可调用的工具接口，并附带工作流指令（skill）教 agent 怎么做逆向调查。（知乎文章定性一致："不是重新开发一个 IDA 或 Ghidra，更像一层 Agent-native 的逆向中间件"）

三层结构：

```
Agent（Claude Code/Codex/…）      ← 提问、追问、写复现代码
  ↕ MCP + skill（工作流指令）
REA（TypeScript 中间件）          ← 17 类目标的检查/追踪/证据组织
  ↕ 外包
Hopper / Ghidra / IDA / JADX /    ← 真正干活的引擎（复用存量安装）
Binwalk / WABT / adb / pwntools…
```

**专家知识的三层拆解**（回应"REA 蒸馏了黑客经验"的直觉——方向对，机制要修正）：

| 层 | 过去在哪 | 现在由谁承担 |
|---|---|---|
| 领域知识（知道什么是导入表、什么值得追） | 专家脑内 + 公开 writeup/文献 | **基座模型预训练语料**——"蒸馏"发生在模型侧，REA 没做也不需要做 |
| 程序性方法论（先看哪、追什么、何时敢下结论） | 师徒制隐性经验 | **REA 的 skill 工作流指令**（手工编码的调查 playbook）+ 官方 showcase 充当 few-shot 范例 + issue 收社区案例反哺——**这是 REA 的真正 IP** |
| 工具手感（让引擎吐出要的东西） | 千小时操作经验 | **MCP 封装 + 结果契约**，工具输出直接进 agent 上下文 |

两个精确化补充：

1. **不是"纯接线"**：JS/Electron（模块/IPC 边界/source map）、.NET（CIL 解析）、Go 二进制（内建静态检查）等托管代码类目标的分析器是 REA 用 TS 自研的真实逆向工程，开箱即用；外包引擎的仅是"原生深度分析"（Hopper/Ghidra/IDA）——准确定位是"**托管代码类自研分析 + 原生类外包引擎**"
2. **证据契约管住幻觉**：每个结论附 evidence + limitations——把 LLM 最弱的可信度问题变成可审计输出，这是"方法论编码"能落地的前提（分析本地进行，但工具结果会经过 agent 的模型供应商，数据政策在供应商侧）

这与 LocalAI 的定性模式同构：**门面/编排层吃掉价值，引擎仍是引擎**。逆向能力的上限仍由 Ghidra/IDA 的反编译质量 + 模型推理耐力决定，REA 降低的是"专业工具 ↔ agent"的接线成本。

## 3. 能力矩阵：17 类目标（快速扩张中）

| 类别 | 目标 | 引擎依赖 |
|---|---|---|
| 原生 | Native binaries（伪代码/汇编/符号/交叉引用） | Hopper/Ghidra/IDA |
| 原生 | Offline ELF 布局、Recorded Linux crashes | pwntools（Linux x64） |
| 原生 | Go binaries（编译器版本/模块/构建设置） | **内建**，无需装 Go |
| 字节码 | WASM（WAT 解码）、EVM（selector/参数推断） | WABT 1.0.42 |
| 托管 | JavaScript/Electron（模块/IPC/source map）、.NET assemblies（CIL） | 无需引擎（静态） |
| 动态 | Websites（Chrome 系浏览器）、网络抓包（HAR/mitmdump）、进程行为（PTY） | 浏览器/mitmproxy |
| 移动 | Android APK（headless JADX+JDK）、真机（adb）、JEB 项目、Android resources（Apktool） | 外部工具 |
| 其他 | 固件（Binwalk/Unblob）、Apple 包资源 | 外部工具 |

⚠️ 09-27 的 CSDN 报道还写"8 类目标"，如今 README 已是 17 类——**目标矩阵两周内翻倍**，迭代极快（README 自己也提醒"REA changes quickly"）。Windows 用户注意：Ghidra 的 Windows 支持官方标注 experimental。

## 5. 净值判断

| 维度 | 判断 |
|---|---|
| 热度真实性 | **真**——GitHub API 数据 + 单日万星级增速，非自媒体互吹 |
| 能力边界 | AI 可靠的是"解释 + 局部重建 + 证据链"，不是"整体还原"；大目标（混淆重、体积大）会耗尽模型上下文/限流 |
| 冲击模式边界 | 该范式成立需三条件齐备：**成熟 CLI 工具存量 + 公开方法论语料 + 可验证证据回路**（重建可测、结论可溯源）；剪映案例卡壳恰因反馈回路弱、目标大——满足条件的细分场景会被同样中间件化，私有知识密集/无验证回路的领域暂时抗冲击 |
| 依赖结构 | 价值在接线层；深度原生分析仍受制于 Ghidra/IDA 存量安装与 license |
| 与 Jev 跟踪线的呼应 | 同一个叙事的三件套：AI 中间件吞噬的都是"隐性知识变现"环节——**Jev 吞决策经验（快思考），REA 吞调查经验（方法论编码），AgentRQ 吞人机断点管理经验（HITL）**；agent 生态的价值正在"层间协议 + 方法论编码"上沉淀，而非引擎本身 |

## 6. 与投石的关联（克制三条）

1. **自用生产力**：遇到"无源码理解遗留系统/私有协议/混淆前端"时，`npx rea-agents@latest setup` 一条命令接入 Claude Code（需 Node 22.19+/24.11+/26+），上手成本约 20 分钟；注意仅用于有授权目标
2. **范式模板**：REA 验证了"存量专业工具 → MCP 封装 + skill 工作流指令"的改造模式——若要把 ToG 领域工具（标书比对、合规检查、评测器）agent 化，这是现成蓝图（比自研引擎便宜两个数量级）
3. **亮哥 AgentInfra 线的对照组**：agent 工具生态爆点的最新样本（一周 10 万星 = 开发者对"agent 摸到真实世界工具"的饥渴度），评估 agent infra 赛道需求方向的免费信号
