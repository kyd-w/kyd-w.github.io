## 工作假设（当前范式判断，2026-10-12 版）

下一阶段垂直领域 agent 的三特征范式：**快（决策分层）、瘦（LLM 退场）、可验证（证据与校准）**。

1. **快**：高频小决策（路由/分类/门控）从 LLM 挪入独立决策层——弱形式是确定性规则（现在就能做），强形式是 Jev/Laya 类校准决策模型（成熟后换芯）；弱形式是强形式的接口
2. **瘦**：LLM 从运行时依赖降级为**开发时依赖 + 异常处理器**——"编译，而不是解释"：开发时 LLM 生成 playbook/skill/脚本（可复用资产），运行时只在 playbook 未命中的新情况兜底
3. **可验证**：快和瘦没有信任只是便宜地犯错——Jev 的校准概率、REA 的证据契约、playbook 的验证命令是同一件事的三个面；分层升级架构能部署的前提是每层自带验证回路

由此推导的**分层升级架构**（escalation architecture，与 SRE 自动化修复同构）：

```
Tier 0  确定性执行：playbook 命中 → 执行 → 验证        （无 LLM，绝大多数流量）
Tier 1  快速决断：路由/分类/置信度（规则 → Jev 类模型）   （毫秒级，微量成本）
Tier 2  LLM 推理：新情况根因分析                        （贵，按需）
Tier 3  人工断点：危险操作审批（HITL，AgentRQ 验证的模式） （最贵，例外）
设计目标：让流量死在低层，LLM 和人都是异常处理器
```

配套判断：**资产类别从"模型"转向"编码后的专家经验"**（skill/playbook 资产化）；价值从 harness 编排层（最薄、最先商品化）向上（方法论编码）和向下（确定性内核+决策层）迁移。

## 范式漂移风险（对"明年落地"类计划的评估框架）

对长周期落地的计划，核心风险往往不是能力与眼光，而是范式演进速度：Jev 这种异轨爆点可能直接改写方向。

层的**衰减速度**不同，计划的耐久度 = 其假设所在层的耐久度：

| 层 | 衰减速度 | 对 2027 落地计划的含义 |
|---|---|---|
| 模型能力 | 周 | 任何押注具体模型能力的假设默认一年内过期 |
| Harness/编排 | 月 | 已被商品化，不可作为价值锚点 |
| 协议（MCP/ACP） | 季度 | 可依赖但需松耦合 |
| **方法论/领域专家编码** | **年** | 唯一值得重仓的层；且编码过程无捷径（冷启动即护城河） |

评估动作：把计划的价值假设按层拆开——若主要价值坐在快衰减层，范式漂移风险不可控；若能沉入慢衰减层（垂直方法论资产、验证回路），则范式变化反而是利好（每次范式升级都在抬高方法论资产的需求）。

异轨爆点（维度 7）的监测口径：**会改写分层结构本身**的事件——新模型类别（Jev 式）、协议范式更替（MCP 之后）、交互形态变化（agent 数量级跳跃）、硬件/成本结构突变。出现即触发本工作假设的全量复审。
