# tryboxi（karthikponna/tryboxi）项目调研

> 调研日期：2026-11-05 ｜ 来源：GitHub repo/API（当日快照：85 ⭐ / 6 fork / 1 open issue，2026-10-20 创建，最后 push 2026-10-25）+ README 全文 + 作者 X（@karthikponna19）+ TrendShift agent-sandbox 榜单 ｜ 触发：用户点名求证（"Go 语言的 AI agent 沙箱项目"）
> 状态：**认知归档**——"Go + AI agent 沙箱"说法成立且工程质量远超同 star 级，但单人两周新项目 + 主力平台仅 macOS，按学习样本收，不按工具收

## 1. 一句话定位

**"E2B，但在你自己电脑上"**：给 Cursor / Claude Code / Codex / 自研 harness 提供一次性 Linux microVM（Ubuntu 24.04 + 独立内核），agent 在里面跑测试/装依赖/起服务/执行不可信代码，代码不出本机、$0。主体纯 Go（GitHub language: Go，四个二进制全 Go；官网 Next.js），MIT，作者 Karthik Ponna（印度，AI 工程师，个人项目）。

## 2. 核心定性

**"Go 的 AI agent 沙箱"完全成立**——不是蹭概念：host daemon、guest PID 1 agent、MCP 适配器、CLI 四件套全 Go，自建 vsock gRPC 通道、gVisor 用户态网络栈、SQLite+sqlc、OTel 全套。

**定位是"本地 microVM 沙箱"这一层的最新样本**：E2B（云）→ K8s（kubernetes-sigs/agent-sandbox）→ Docker（strands-agents/box）→ 本地 microVM（tryboxi、microsandbox）。差异化全在"安全边界设计"而非"能跑 VM"。

机制拆解（五件套）：

```
1. sandboxd 守护进程   host 侧大脑：HTTP API（unix socket，可选 TCP+token）、
                      vCPU/内存调度账本、VM 驱动、快照、工作区同步、出网策略
2. sandbox-agent      每个 VM 的 PID 1（静态 Go 二进制，initramfs 投递），
                      gRPC over vsock：exec/PTY/超时/文件读写/输出 spool
3. VM 后端双驱动      macOS = Virtualization.framework；Linux = Firecracker+netns
   （网络双栈）        macOS 出网走 gVisor 用户态 netstack，Linux 走 netns+nftables
4. sandbox-mcp        MCP stdio 适配器：11 个 sandbox_* 工具；且 mcp install
                      同时写入 agent 规则（Cursor rules / Claude skill / AGENTS.md），
                      教 agent"何时该进沙箱"而不只是"怎么进"
5. 工作区单向闸门     repo 只进不出：host→VM 增量同步；改动仅经 diff/apply/pull
                      回流，全程备份可 undo；无 virtio-fs 共享目录，文件只走 vsock 拷贝
```

**最有教学价值的两处设计**：

- **密钥永不入 VM**：VM 内只见占位符；出网代理（本地 CA 终止 TLS）仅在允许的 host 上换成真值，回显值会被清洗，占位符发往别处直接拦截；git 代理只对允许的仓库注入 token、拒绝向允许分支之外 push。含密钥的命令/env/stdin/文件在源头就被拒。
- **出网默认白名单**（包 registry、GitHub、Ubuntu 镜像），loopback/LAN/链路本地/元数据地址/CGNAT 永久封禁 + DNS 应答校验；agent 可经 `sandbox_network` 工具"申请放行某 host"——人批准。

## 3. 架构观察

- **性能工程认真**（M4 16GB 实测）：热池取沙箱 20–50ms、金快照建 0.5–0.6s、暂停恢复 0.5–0.7s、fork ~0.8s、冷启到 agent 就绪 1.2s、exec 往返毫秒级——这是"把 microVM 当函数调用"的工程投入
- **数据安全护栏写进代码**而非文档承诺：`safefs.RemoveUnder` 围栏删除、apply/pull 拒绝绝对路径/`..`/逃逸符号链接/`.git/`、3-way merge 用临时文件跑 `git merge-file` 从不碰 index、默认不同步 `.env*`/`*.pem`/`id_*` 等
- **可观测性全套**：Prometheus + OTel trace（`sandboxctl trace` 出逐阶段瀑布图）+ Grafana dashboard 随仓附带
- 上手路径即源码构建（`make images` 约 3 分钟 Docker 内构建 rootfs + `make build`），未见预编译发布物；运行时免 root、免 Docker、免 Lima

## 6. 与投石的关联（克制三条）

1. **威胁模型抄作业**：若 AgentInfra 线走到"agent 执行面隔离"方案阶段，本 README 的 Data safety 一节（单向同步、围栏删除、密钥不入 VM、白名单出网、ask-to-allow）就是现成的需求 checklist，MIT 无引用负担
2. **"MCP + 规则同装"模式**：`mcp install` 同时写 `.cursor/rules` / `.claude/skills` / `AGENTS.md` 教 agent 何时用沙箱——工具分发带行为约定的做法值得进自家 agent 产品设计笔记

## 8. 延伸：本地 microVM × 云端沙箱——行业方案对比

> 增补于同日。由 tryboxi 触发的横向对比，只谈行业已存在的公开方案；图谱经 TrendShift agent-sandbox 主题榜（2026-11 快照）与 Northflank / LogRocket / Fly.io / Koyeb 等对比文核对。

### 8.1 方案图谱（部署位置 × 隔离技术）

| 档位 | 隔离技术 | 代表（2026-11 快照） | 备注 |
|---|---|---|---|
| 本地·OS 原生 | 进程级沙箱 | Claude Code 原生 sandboxing；strands-agents/box（Rust，default-deny 策略） | harness 自带，最轻，共享内核 |
| 本地·容器 | Docker / rootless 容器 | getkern/kern（无守护容器运行时）等 | 轻量，共享内核 |
| 本地·microVM | 独立内核（VZ / Firecracker） | **tryboxi**、microsandbox、brig-sh/brig（Go）、clawk、microsoft/nvx（跨平台） | 2026 集中爆发的一档 |
| 自托管·远程 | 自有服务器上的 microVM | pi-pod/pipod、BitMiracle-AI/Dormice（自称"沙箱界的 SQLite"，E2B 兼容、闲时零成本）、useagent | 本地与云之间正在成型的第三路线 |
| 云·托管 API | Firecracker / 容器 | E2B（每 agent 独立 Firecracker microVM）、Daytona（有状态+devcontainer/Git）、Modal、Fly.io Sprites、Vercel Sandbox、machine0 | 按量计费，赛道最成熟 |
| 集群·K8s | 容器 / microVM | kubernetes-sigs/agent-sandbox、kvcache-ai/AgentENV（分布式 agent 环境平台） | 面向自有集群的治理形态 |

### 8.2 分界线：负载天然属于哪边

| | 本地（含自托管远程） | 云端托管 API |
|---|---|---|
| 不可替代 | 交互迭代回路（测试/lint/dev server——延迟敏感）；代码与数据不出域；边际成本≈0 | 规模化并行（agent 军团/批量评测）；重型渲染转码；7×24 常驻登录态；地理分布的网络身份；弹性伸缩 |
| 天花板 | 单机内存/CPU；无水平扩展；无常驻公网；团队共享态难 | 数据出域；按量成本；冷启动与网络往返；供应商绑定 |

**判词**：本地 microVM 工程一旦成熟到函数调用级（热池 20–50ms、冷启 1s 级——tryboxi 已实证），"笔记本跑得动的负载留在本地"就成为默认——免费、私密、零迁移。云端可收费的负载向"笔记本跑不动的"收敛：规模化批处理、媒体流水线、常驻服务、浏览器农场。两边不是替代关系，是**分界线固化**。

### 8.3 "VM 太重"的 2026 版答案

- Firecracker 谱系（AWS Lambda 同源）+ 热池/快照/fork 工程化，已把 microVM 延迟压到函数调用级——单机场景"VM 太重"不再成立
- 但行业实际答案不是二选一：**按威胁模型选档**（OS 沙箱 → 容器 → microVM），云端高密多租场景仍在用轻量运行时/gVisor 档位换密度
- 2026 新信号：microsoft/nvx 做跨平台 microVM（补 Windows 缺口）；Rust 阵营进场（strands box、brig）——本地 microVM 正从极客玩具转向平台标配

### 8.4 设计共识清单（本地/云端同向收敛）

1. 出网默认拒绝/白名单 + agent"申请放行"（ask-to-allow）
2. **密钥留在执行环境外**：tryboxi 用占位符+出网代理置换；strands-agents/box 用 credential injection——两个独立阵营同一设计，强收敛信号
3. 工作区单向闸门：sync 进 / diff·apply·pull 出 / 全程可 undo
4. 快照/暂停恢复/fork 成一等公民——对应常驻负载"驱逐-恢复"这一最难的系统问题
5. 沙箱成为 harness 配件：MCP 注册 + agent 规则同装（`.cursor/rules` / `.claude/skills` / `AGENTS.md`）
6. OTel/Prometheus 可观测从第一天标配

### 8.5 赛道判断（2026-11 快照）

- **类别爆发年**：TrendShift agent-sandbox 榜几乎全部标 "New 2026"——大厂（Microsoft/Perplexity/AWS strands）、云商（Fly/Vercel/Modal）、个人开发者（tryboxi/brig/clawk）同时进场；有中文长文断言"编码 agent 护城河已从模型转移到沙盒"（单一来源观点，未证实）
- **反向力量**：harness 原生 sandboxing + "MCP+规则同装"模式 → 沙箱从独立基建变成 agent 平台配件，独立 sandbox 服务的长期估值逻辑受压（与 AgentRQ 调研中"平台收编中间层"同构）
- **使用者决策树**：交互开发回路 → 本地 microVM（免费+私密）；规模化/常驻/媒体 → 云端 API；中间态（自己的闲置服务器）→ pipod/Dormice 类自托管远程正在补位
